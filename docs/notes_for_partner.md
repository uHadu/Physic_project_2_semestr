# Замечания по ядру (для автора solver.py / components.py)

Ядро не изменялось. Ниже перечислено, чего не хватило или что похоже на ошибку.

1. **В core.md описаны файлы, которых нет в репозитории:** `netlist.py`, `analysis.py`,
   `plot_data.py` (быстрый старт с `parse_netlist`, `sweep`, `fit_resistance`, `iv_plot`).
   Пример из core.md не запускается.
2. **`Solution.reports(seed=...)` создаёт новый `random.Random(seed)` при каждом вызове.**
   При серии с одним `seed` шум во всех точках одинаковый, то есть превращается в систематическую
   ошибку. Предложение: принимать готовый `rng` (как `Solution.report`) или явно написать об
   этом в документации. В `experiment.run_series` это обойдено: у каждой точки свой seed.
3. **Модель шума расходится с README:** в ядре шум равномерный в [−Δ; +Δ], в README
   был нормальный с σ = γ·предел/100 %. По решению команды README приводится к ядру.
4. **Утечка `G_MIN = 1e-12` См из каждого узла на землю даёт систематическую ошибку ≈ −R·G_MIN.**
   При R = 1 МОм это 10⁻⁴ %, при 1 ГОм уже 0,1 %. В схеме Б при R ≳ 700 кОм эта добавка больше
   «настоящей» ошибки метода R_A/R, и кривая δ(R) делает провал (поэтому на графике δ(R)
   диапазон ограничен 300 кОм). Можно включать G_MIN только для висящих узлов или вычитать
   ток утечки в отчёте.
5. **Нагрев резистора не моделируется:** README (раздел 1) требует ограничить мощность P_max,
   а в ядре есть только флаг `overheated`, R от температуры не зависит. При P_max = 0,25 Вт
   по умолчанию резистор 1 Ом «перегрет» уже при 1 В. Интерфейс выводит предупреждение.
6. **Показания прибора при шуме могут выйти за предел:** шум добавляется после выбора предела,
   поэтому значение около предела может оказаться больше него без `overload`.
7. **У перегруженного прибора в отчёте нет ключа `resolution`** (у нормального есть).
   Набор ключей лучше сделать одинаковым.
8. **Мелочь:** в комментарии `ParamSpec.kind` перечислены `float | bool | list | str`,
   но `CustomElement` использует ещё `kind="table"`.
